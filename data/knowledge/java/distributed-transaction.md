# 分布式事务 2PC / TCC / 本地消息表
## 2PC 两阶段提交
面试官常问：2PC流程，协调者、参与者，优缺点？
答题要点：准备阶段：协调者通知所有参与者预提交，锁定资源；提交阶段：全部成功则通知提交，任意失败全部回滚。缺点：协调者单点、准备阶段资源长时间锁定，阻塞，性能差。
常见误区：2PC可以解决所有分布式事务；阻塞问题，适合短事务，不适合高并发业务。

## TCC 事务
面试官常问：TCC Try Confirm Cancel 三个阶段含义？
答题要点：Try：预留资源、冻结；Confirm：确认执行业务；Cancel：释放预留资源回滚。TCC是业务侵入式，需要业务代码写三个接口，无锁，性能好。
常见误区：TCC框架自动生成Confirm/Cancel；框架只是编排，业务代码自己实现，侵入性强。

## 本地消息表（可靠消息最终一致性）
面试官常问：本地消息表方案流程？
答题要点：本地事务：业务数据 + 消息记录落库；定时任务扫描消息表，投递MQ；消费者消费成功更新消息状态；失败重试。核心是本地事务保障消息一定发出。
常见误区：本地消息表不会重复；依旧会重复投递，消费端必须幂等。

## 事务选型对比
面试官常问：最终一致性和强一致性怎么选？
答题要点：强一致性（2PC）适合金融转账，低吞吐；TCC、本地消息表、事务消息是最终一致性，高并发互联网业务主流。RocketMQ事务消息是本地消息表的封装。
常见误区：事务消息可以做到强一致；依旧是最终一致性，只是封装了消息表逻辑。
