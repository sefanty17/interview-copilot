# HashMap 扩容与红黑树转换
## 底层结构与hash计算
面试官常问：HashMap的hash方法为什么要高低位异或？
答题要点：hash函数：`h = key.hashCode() ^ (h >>> 16)`，把hash值高16位和低16位异或。table数组长度一般不大，取模只用到低位，高位信息被丢弃，异或之后让高位参与散列，减少hash冲突。
常见误区：HashMap的hashCode直接用来定位；不是，是扰动之后的hash值；数组长度是2的幂，用`(n-1)&hash`代替取模%，更快。

## 扩容机制与重新hash
面试官常问：HashMap扩容什么时候触发？扩容后元素怎么分配？
答题要点：负载因子默认0.75，元素数量>容量*负载因子触发扩容，容量翻倍。扩容时，元素要么留在原下标，要么在原下标+旧容量位置，不需要重新计算hash，只看hash旧容量那一位二进制位是0还是1。
常见误区：扩容所有元素都重新hash；JDK8优化后不需要重新算hash，只判断bit位；负载因子0.75是空间和冲突概率的权衡。

## 链表和红黑树转换条件
面试官常问：链表什么时候转红黑树？红黑树什么时候退化成链表？
答题要点：链表长度≥8，并且数组容量≥64，才转红黑树；如果数组容量小于64，优先扩容，而不是树化。红黑树节点数量≤6，退化成链表。中间7是缓冲，防止频繁来回转换震荡。
常见误区：链表到8就一定会树化；忽略数组容量64这个前置条件；很多面试直接漏这个条件。

## fail-fast 快速失败
面试官常问：什么是fail-fast？HashMap迭代为什么快速失败？
答题要点：迭代器遍历的时候，modCount记录修改次数；迭代开始记录expectedModCount；如果遍历过程put/remove，modCount变化，抛出ConcurrentModificationException。
常见误区：fail-fast是并发安全机制；它只是快速检测，不保证线程安全；ConcurrentHashMap迭代没有fail-fast，是弱一致性。
