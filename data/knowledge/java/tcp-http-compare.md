# TCP握手挥手、HTTP1.1 vs HTTP2
## TCP三次握手四次挥手
面试官常问：三次握手为什么不是两次？四次挥手为什么不是三次？
答题要点：三次握手：确认双方收发能力都正常；两次握手只能确认客户端发、服务端收，服务端发给客户端的链路无法验证。四次挥手：TCP是全双工，关闭是单向关闭，A发FIN只是A不再发，B还可以继续发数据，B发完自己的数据再发FIN。
常见误区：FIN报文发出之后立刻不能收发；收到FIN代表对方不再发送，本方还可以继续发数据。

## HTTP1.1 痛点
面试官常问：HTTP1.1有哪些问题？长连接、管线化？
答题要点：队头阻塞：同一个连接上请求串行，一个慢请求阻塞后面；管线化支持差，浏览器基本不实现；头部冗余，每次请求都带上完整header。长连接keep-alive减少握手开销，但解决不了队头阻塞。
常见误区：HTTP1.1长连接没有队头阻塞；长连接只是不用反复握手，请求依旧串行。

## HTTP2 核心优化
面试官常问：HTTP2多路复用、二进制帧、头部压缩、服务器推送？
答题要点：多路复用：一个TCP连接，多个流并行，帧带流id，解决队头阻塞；二进制帧代替文本；HPACK头部压缩；服务端推送资源。
常见误区：HTTP2彻底解决队头阻塞；它解决HTTP层队头阻塞，TCP丢包还是会阻塞整个连接。
