# JMM 与 happens-before
## JMM 基础模型
面试官常问：JMM是什么？为什么需要JMM，而不是直接操作CPU缓存？
答题要点：JMM（Java内存模型），是一套抽象规范，屏蔽不同CPU架构缓存、指令重排的差异，定义线程之间共享变量的可见性、原子性、有序性规则。底层CPU有缓存行、寄存器，多线程读写共享变量会出现缓存不一致、指令重排，JMM向上提供统一抽象：主内存放共享变量，每个线程有本地工作内存（寄存器+缓存）。
常见误区：JMM不是真实硬件，不是JVM内部的一块内存区域，是**语义规范**；很多人把工作内存等同于JVM栈，是错误的。

## 三大特性：可见性、原子性、有序性
面试官常问：JMM保障的三个特性分别是什么？volatile能保证哪几个？
答题要点：原子性：一次操作要么全部成功，要么全部失败，中间不能被打断，比如i++不是原子操作；可见性：一个线程修改共享变量，其他线程立刻感知；有序性：禁止指令重排。volatile只能保证可见性、禁止重排，**不能保证原子性**，所以volatile不能替代锁。
常见误区：很多人说volatile可以保证原子性，在i++场景直接踩坑；指令重排不是CPU乱执行，是编译器、CPU为了性能做的重排，只要不改变单线程语义就允许重排。

## happens-before 八大规则
面试官常问：happens-before是什么？列出核心规则，怎么理解？
答题要点：happens-before是JMM定义的偏序关系：A happens-before B，代表A操作的结果对B可见，并且A不能重排到B之后。核心规则：程序顺序规则、volatile写在读之前、锁解锁在加锁之前、线程start、线程join、传递性、线程中断、final规则。它是强可见性规则，不是代码执行顺序。
常见误区：happens-before不等于代码执行先后；满足happens-before，才保证可见性；没有任何happens-before约束的两个操作，JMM不保证可见性，允许重排。

## 双重检查锁DCL的JMM原理
面试官常问：DCL单例为什么要加volatile？不加volatile会出现什么问题？
答题要点：不加volatile时，new对象分为分配内存、初始化对象、赋值给引用三步，指令重排可能先赋值、后初始化，别的线程拿到半初始化的对象，NPE或者数据错乱。volatile禁止这三步的重排，保证初始化完成之后，引用才赋值。
常见误区：很多人以为DCL不加volatile只是可见性问题，根源是**指令重排**；static静态内部类单例不需要volatile，依靠类加载初始化的天然锁。
